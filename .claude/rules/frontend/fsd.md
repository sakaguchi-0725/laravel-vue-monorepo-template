# Feature Sliced Design

## 基本的な概念

- レイヤー、スライス、セグメントの3要素で構成される
- トップレベルのフォルダーはレイヤーと呼ばれる
- スライスはレイヤーとドメインごとに分割する
- セグメントはスライス（または一部のレイヤー）を技術的な目的に応じて分割する

## レイヤー

本プロジェクトでは以下のレイヤーを使用する。

- App: アプリケーションの起動に必要なものを配置する
  - ルーティング
  - エントリーポイント
  - グローバルスタイル
  - プロバイダー
  - etc
- Pages: ページ全体。Featuresを組み合わせてページを実現する。
- Features: プロダクト機能の再利用可能な実装。ビジネスロジック。
- Shared: 特定のドメインに依存しない再利用可能なコード。
  - ボタンやダイアログなどの汎用コンポーネント
  - APIクライアント
  - etc
- 依存方向はapp → pages → features → sharedの一方向のみ

## スライス

- レイヤーをドメインで分割する
- スライスは同じレイヤーないの他スライスを使用してはならない
- 本プロジェクトでは以下の基準に従いスライスを作成する
  - Features: ドメイン単位で分割（例: account, task）
  - Pages: 画面単位で分割（例: account-list、task-detail）

## セグメント

- スライス、およびApp層とShared層はセグメントで構成される
- 本プロジェクトでは以下のセグメントを使用する
  - ui: 表示に関わるもの全て（コンポーネント、スタイルなど）
  - api: APIリクエスト関数
  - model: データモデル、バリデーションスキーマ、ストレージ、カスタムフック（ビジネスロジック）
  - lib: 他のモジュールが必要とするライブラリコード
  - config: 設定ファイルとフィーチャーフラグ
- App層とShared層は独自セグメントを作成して良い。
