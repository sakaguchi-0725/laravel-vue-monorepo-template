# PHP / Laravel コーディングルール

## 型

- 全 PHP ファイルの先頭に `declare(strict_types=1)` を書く
- 引数・戻り値・プロパティのすべてに型宣言を書く。戻り値がないメソッドは `void` を明示する
- `mixed` を使わない。型が定まらない場合はユニオン型か具体的な型に絞る
- 型宣言で表現できる情報を docblock に書かない。docblock は配列の要素型（array shape、ジェネリクス記法）を
  表すときのみ使う
- nullable は `?T` の短縮記法を使う。`T|null` を使わない

## 比較

- 比較は `===` / `!==` を使う。`==` / `!=` を使わない
- `empty()` を使わない。null 判定は `=== null`、空配列は `=== []`、0 は `=== 0` と意図を明示する
- `in_array()` / `array_search()` は第3引数に `true` を必ず渡す
- ショートテナリー `?:` を使わない。`??` か完全な三項演算子を使う

## 制御構文

- 早期 return を使い、`else` を書かない。異常系を先に処理し、正常系をインデントなしの末尾に置く
- 制御構文は本体が1行でも必ず波括弧を付ける

## クラス

- コンストラクタで代入するだけのプロパティは constructor property promotion で書く
- 引数なしの空のコンストラクタを残さない
- DTO と値オブジェクトは `readonly` にする。それ以外のクラスに `readonly` / `final` をデフォルトで付けない
- trait の `use` は1行1トレイトで書く

## 値の表現

- 状態や種別を表すマジックストリング・マジックナンバーは backed enum で表現する
- クラス定数と enum ケースは PascalCase
- enum の backing 値は OpenAPI 仕様書を経由してフロントエンドと共有されるため、仕様書の定義と一致させる

## 命名

- クラス名は役割を表す suffix で固定する（`〜Controller` / `〜Request` / `〜Resource` / `〜UseCase`）
- コントローラ名は単数形にする（`UserController`）
- イベントは時制で表す。発生前は `ApprovingLoan`、発生後は `LoanApproved`
- 公開されない文字列は camelCase。config のキーのみ snake_case
- config のファイル名はケバブケースにする

## ルーティング

- ルーティングファイルにロジックを書かない
- ルート定義は tuple 記法 `[UserController::class, 'index']` を使う。文字列記法を使わない
- URL とルートパラメータ名は OpenAPI 仕様書（`docs/api/*/openapi.yml`）の定義に一致させる
- ルート名は camelCase

## コントローラ

- アクションは `index` / `store` / `show` / `update` / `destroy` のみ。JSON API のため `create` / `edit` は作らない
- これらに収まらないアクションが必要な場合は、アクションを追加せずコントローラを分ける

## バリデーション

- バリデーションルールは配列記法で書く。`|` 区切りを使わない

## 設定値

- `env()` を `config/` 配下以外で呼ばない。設定値は `config()` 経由で取得する

## コメント

- **コメントは書かない。これを既定とする**
- 何をしているか（What）を説明するコメントは絶対に書かない。コードを読めば分かる内容の重複でしかない
- 処理の要約、引数の説明、セクション区切り、`// 〜を取得`・`// 〜を保存` の類はすべて What であり禁止
- 例外はなぜそうしたか（Why）がコードから読み取れない場合のみ。次に限る
  - コードからは導けない業務上の制約や仕様判断
  - 一見不要・不自然に見える処理を残している理由
  - 回避策とその原因（ライブラリの制約、既知の不具合）
- 迷った場合は書かない。命名で説明できることは命名で表現する
- PHPDoc も同じ基準で扱う。型情報の再掲は書かない
